# Vault Structure Philosophy

This document explains the logic behind the numbered folder structure of my Personal Knowledge Base. The goal is to create a scalable, non-alphabetical system that groups related topics into broad categories.

The first digit of the number prefix indicates the category.

---
### ## 00-09: Core Knowledge & Theory 🧠
This range is for the foundational, theoretical pillars of Computer Science. These are the timeless, universal principles that underpin everything else.
- **`00_Concepts/`**
- **`01_Networking/`**
- **`02_Operating_Systems/`**

---
### ## 10-19: Tools & Applications 🛠️
This range is for the practical tools (languages) and the application of those tools in a specific domain (web development).
- **`10_Languages/`**
- **`11_Web_Development/`**

---
### ## 20-29: Portfolio & Practice 🚀
This is for my hands-on work and projects where I apply my knowledge.
- **`20_Projects/`**

---
### ## 30-39: Personal Growth 🌱
This is for topics outside of my core CS curriculum.
- **`30_Natural_Languages/`**


--- 
### ## 40-49: Personal Setup & Configuration workstation️ 
This category is for the "workshop"—the practical documentation of my personal machine configurations, custom scripts, and setup guides. It separates my specific implementation from general theory. 
- **`40_My_Setup/`**

---
### ## 80-99: System & Meta ⚙️
This range is reserved for utility and system-related folders. Placing them in the 80s and 90s intentionally pushes them to the bottom of the file list, keeping them out of the way of my primary knowledge folders.
- **`80_System/`**
- **`90_Templates/`**
