# Tailwind vs Pure CSS

## 📝 One-Sentence Summary
Pure CSS involves writing custom styles and classes, while Tailwind CSS is a utility-first framework that provides pre-defined, single-purpose classes directly in your HTML.

## 💡 Analogy
* **Pure CSS**: 
	* Like **tailoring a suit from scratch**. You design the pattern (`.section-title`), cut the fabric (write specific styles), and sew it together. You have full control, but it takes time. 
* **Tailwind CSS**: 
	* Like having a huge **wardrobe of individual clothing items** (utility classes like `text-xl`, `font-bold`, `mb-4`, `bg-blue-500`). You pick and combine these items directly on the person (in your HTML) to create the final look. It's faster for common styles but relies on the available items.
## 🔑 Key Details
### Pure CSS (Semantic CSS)
* **Approach**: You invent class names that describe the *content* or *purpose* (e.g., `.profile-card`, `.main-navigation`).
* **Styling**: You write CSS rules for these classes in a separate `.css` file.
* **HTML**: Remains relatively clean, containing mostly semantic class names.

**Example:**
```html
<div class="card">
  <h2 class="card-title">Title</h2>
</div>
````

```CSS

/* style.css */
.card {
  padding: 1.5rem;
  border: 1px solid #e5e7eb;
  border-radius: 0.5rem;
}
.card-title {
  font-size: 1.25rem;
  font-weight: 600;
  margin-bottom: 1rem;
}
```

### Tailwind CSS (Utility-First)

- **Approach**: You apply many pre-defined utility classes directly to HTML elements. Class names describe the _style_ they apply (e.g., `p-6`, `border`, `rounded-lg`).
    
- **Styling**: Primarily done within the HTML `class` attribute. Minimal custom CSS is written. Requires a build step to generate the final CSS.
    
- **HTML**: Can become verbose with many classes, but contains all styling information directly.
    

**Example:**
```HTML
<div class="p-6 border rounded-lg">
  <h2 class="text-xl font-semibold mb-4">Title</h2>
</div>
```

```CSS

/* style.css (Generated by Tailwind build process) */
/* Contains only the styles for the utilities used above */
```

## 👍 Pros & 👎 Cons

### Pure CSS

- **✅ Pros**: Clean HTML, full control, encourages semantic naming.
    
- **❌ Cons**: Can require lots of context switching between HTML and CSS, naming conventions can be hard, potential for large CSS files if not managed well.
    

### Tailwind CSS

- **✅ Pros**: Rapid prototyping & development, enforces consistency, less context switching, highly optimized final CSS output (via build tools).
    
- **❌ Cons**: Verbose HTML, requires a build step, can feel less semantic initially, steeper learning curve for available utilities.
